# Design Red Flags

> 改寫自 cursor/plugins 的 pstack（`harness/pstack/claude-code/skills/architect/references/design-red-flags.md`，MIT License，Copyright (c) 2026 Lauren Tan）。

**用途**：Phase 2 覆寫 `design.md` 之前，把草稿對照下面八條。命中任何一條，就修改設計；改不掉的，把「命中哪一條、為什麼接受」寫進 `design.md` 的 `## Trade-offs`。沒有命中就不必寫。

**前提**：假設下一位貢獻者是一個只看自己打開的那幾個檔的 agent。它不會讀全專案，會照著它先看到的那一種寫法抄，會走最短、能編譯的路。對人類顯而易見的「大家都知道不要這樣」，對它不成立。

## 1. 淺模組
- 徵兆：呼叫者要協調好幾個方法才能完成一件事；公開選項暴露內部階段或實作選擇；學會介面仍然不能省下學實作。
- 自問：介面背後藏了多少能力與政策，相對於介面本身的大小？
- 處置：收成一個介面，把實質行為放到後面。深的是模組，不是呼叫鏈；呼叫鏈很深只是把理解分散到各層。

## 2. 資訊洩漏
- 徵兆：同一個內部決定（表示法、政策、協定細節）出現在不只一個模組；公開 re-export 傳輸層或線路上的型別。
- 自問：改這個決定要同時改幾個地方？
- 處置：在介面後面把外部資料解析成領域型別；儲存 schema、框架物件、協定細節留在私有範圍。

## 3. 依時序切分
- 徵兆：模組按執行順序切成載入、驗證、轉換、儲存，每一段都重複同一個表示法與它的不變量。
- 自問：這些模組各自擁有的「知識」是什麼，還是只擁有「步驟」？
- 處置：圍繞領域知識與擁有權分組。在不同時間執行的方法，只要守護同一批決定，仍可屬於同一個模組。

## 4. 穿透方法
- 徵兆：一個方法把相同的引數原封不動轉給另一個形狀相同的方法，沒有加任何東西。
- 自問：這一層有加政策、轉接或獨立的抽象嗎？
- 處置：刪掉它，或把責任移給真正能完成操作的模組。只有加了政策、轉接或獨立抽象的轉發邊界才保留。

## 5. 分裂的擁有權
- 徵兆：不只一個模組寫同一份狀態，或各自保留一份副本。
- 自問：改其中一個 writer 的人，看得到另外幾個嗎？
- 處置：每份狀態只有一個擁有者；其他模組讀取，或請擁有者去改。

## 6. 同一件事兩種做法
- 徵兆：設計同時支援兩種以上的方式完成同一件事。
- 自問：下一個 agent 會抄哪一種？
- 處置：只留一種。同一次變更把呼叫者搬過去，並刪掉其他做法；留著的每一種都會繼續長出新的呼叫者。

## 7. 可匯入的內部
- 徵兆：外部呼叫者可以直接匯入模組的內部。
- 自問：外部匯入內部時，建置會失敗嗎？
- 處置：讓內部在模組外無法到達，外部匯入就讓建置失敗。否則它們會成為介面的一部分。

## 8. 手動同步清單
- 徵兆：兩處以上列出同樣的項目，新增一項就要改每一份。
- 自問：只看見其中一份的人，會只改那一份嗎？
- 處置：只留一份，其餘從它推導。推導不了的，讓兩份不一致時建置失敗。
