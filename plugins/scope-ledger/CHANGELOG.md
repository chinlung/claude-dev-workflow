# Changelog

All notable changes to the `scope-ledger` plugin will be documented in this file.

## [1.1.0] - 2026-10-18

### Added

- **`scope stats`** (`scripts/scope-stats.cjs`): sums the Log's per-round outcomes per review tool across one or many projects (`--project <dir>`, repeatable; `--all` decodes the `~/.claude/projects/*` directory names against the file system) and prints rounds, findings, fixed / deferred / wrong / intentional / moot, precision = (fixed + deferred) / judged, and the open items per source in In scope, Deferred and follow-ups; `--json` for machines. A reviewer's noise is what people did with its findings, not what it says about itself — this is the number that decides whether a second opinion earns its cost or a piloted tool stays. The triage hook tags a source with the name the review was invoked by — qualified when the model called the Skill (`code-audit-rigor:review-branch`), short when the user typed the slash command — so a fixed alias table merges the known forms into one row (`claude-security:scan` → `claude-security`, `codex:review` → `codex`, …) while different plugins' same-named tools (`pr-review-toolkit:review-pr`, `engineering:code-review`) keep their qualified names; a generic "strip the prefix" would have merged those and split `claude-security`. Tested in `tests/scope-stats.test.sh` (both Log forms, English and Chinese field names, qualified and short sources, an unparseable line reported by number, `--all` with a hyphenated project path).

### Changed

- **Log line outcomes are five buckets**: `<n> findings → <f> fixed / <d> deferred / <w> wrong / <i> intentional / <m> moot` (was `adopted / deferred / noise`). `wrong` is the reviewer being mistaken, `intentional` is behaviour that was by design and the reviewer lacked the context, `moot` is true but changes nothing — three outcomes that were one bucket before, of which only the first is the reviewer's fault. The 1.0.x form is still read (adopted → fixed, noise → wrong). The hooks' grammar is unchanged: Log lines were never parsed by a hook.
- `facts`: a `/review-branch` 2.1 results file already carries `introduced` on every suggestion (the same in-diff judgement, computed by its `annotate`); the skill says to use it as `in_diff` instead of re-running `facts` for those findings.

## [1.0.4] - 2026-10-17

### Fixed

- **The skill names the directory the hooks use, and its own steps stop depending on the shell's current directory.** `<project>` was never defined, so a model working on another repository could write the ledger there, where no hook ever reads it: the gate, the Stop check and the SessionStart replay would all stay silent. The skill now defines `<project>` as the hooks' project directory (`CLAUDE_PROJECT_DIR`), which neither follows a `cd` nor is necessarily the repository being edited, and tells the model to read it from the hooks' own messages, because the Bash tool cannot see that variable. Every `.claude/…` path is `<project>/.claude/…`, `init`'s git commands (`rev-parse`, `check-ignore`, `ls-files`, the `rm --cached` advice) run as `git -C <project>`, and `facts` is called with an explicit `--repo` and its `root` is checked, because its default is the shell's current directory and a wrong repo would silently decide which findings count as part of this change. README's limits say the same.

  **Why:** the Bash tool's working directory persists between calls and is shared by parallel ones, so a `cd` anywhere moves it. Checked on 2026-10-17 against the hooks: all six resolve the project from `CLAUDE_PROJECT_DIR` and never drift; the model-run steps were the part that did.

## [1.0.3] - 2026-10-17

### Added

- **`add "<request>"`: the next request on the same line of work goes into the existing ledger, not a new one.** `init` refused whenever a usable ledger existed and asked for `done` first, so a run of imperatives for one piece of work (build it → commit → review again → commit → push) produced one ledger per imperative, each with its own init, Log, `done` and memory entry: one measured session opened six ledgers, three of them with the one-word goal `commit`. `init` on a ledger whose In scope is fully ticked now appends the request (verbatim, `← 來源: user`, one Log line) and leaves goal, mode and `review_rounds` alone; on a ledger with open items it still refuses and points at `add` or `done`. A different repository, a different feature, a long-idle ledger or a harvest-type request on a converge ledger still start a new ledger. Skill text only — no hook reads the verb; the Stop hook never blocked on a fully ticked ledger, so leaving one open costs nothing.

- **`scripts/scope-facts.cjs`: the mechanical half of a finding's triage, computed instead of judged.** The converge policy's first question — does this finding belong to this change? — is whether its file:line sits inside a hunk of the branch diff; the sibling, MUST-rule and boy-scout exceptions are a text search, a guideline grep and a line count. Every triage so far answered those by hand, one finding at a time, and a review of the `tree` workflow found a scope-vs-diff mismatch of exactly that kind. The script reads a JSON list of findings and attaches `in_diff` / `nearest_hunk_distance` / `file_in_diff` / `untracked`, `hunks`, `patch_lines`, `sibling` candidates (the evidence's first backticked snippet, else the source line, searched with `git grep --untracked`, the finding's own line excluded) and `must_rules` candidates (lines of AGENTS.md / CLAUDE.md / .claude/CLAUDE.md / CONTRIBUTING.md / docs/CONTRIBUTING.md that read as a rule — MUST, 必須, 一律, 禁止, 不得, 絕不 — and share words or two CJK bigrams with the claim), plus a summary. Base: `--base`, else the merge-base with `origin/HEAD`, else `HEAD`; the diff covers commits since the base and the working tree; untracked files count as wholly added; absolute paths are resolved through symlinks before being made relative (macOS `/tmp`), and a path that resolves outside the work tree — `../`, an absolute path elsewhere, a symlink inside the repository pointing out, a symlinked guideline file — is marked `outside_repo` and never read. Whole-file changes come from `diff --name-status` / `--numstat` (`change_kind`: modified, added, deleted, binary, mode, typechange, untracked), so a deleted or binary file is in the diff although `-U0` prints no hunk for it; git runs with `core.quotePath=false`, explicit `a/` `b/` prefixes and `--no-renames`; a `+++` line names a file only between `diff --git` and the first hunk (inside a hunk it is an added line that begins with `++ `), the tab git appends after a name with a space is dropped, headers are C-unquoted and `git grep` / `ls-files` read `-z` records, so non-ASCII, colon, quote and tab file names match; a line given as a digit string is coerced, any other non-integer is `line_invalid` and never in the diff; when neither `--base` nor `origin/HEAD` exists the fallback is reported as `base_fallback` and on stderr; empty or TTY stdin exits 2 with a message. The same output is the neutral `state` for `jev_decide` — writing that state by hand was why the classifier kept being skipped — and the skill's triage section now starts with `facts`. Verb `facts <findings.json>` added to the skill.
- **A Workflow review counts as a round.** `scope-review-triage.sh` only knew Skill calls, typed slash commands and Agent dispatches, so a review run through the `Workflow` tool (the `tree` workflow's `review` recipe, `claude-security:scan`) advanced no round and injected no policy — two `tree` reviews in one measured session, and a review → fix → review loop on that path could never reach the convergence warning. The PostToolUse matcher now includes `Workflow`; a run whose `name` (or `scriptPath` basename without `.js`) is `tree` with recipe `review` — the script's default when the recipe is omitted; `args` read as an object or as a JSON string — or `claude-security:scan` counts and injects; a resume (`resumeFromRunId`) injects only; `tree`'s other recipes, an inline `script` and unknown workflows stay silent. The `~/.claude/scope-ledger-review-patterns` lines apply to workflow names as well. The verdict is computed inside jq by equality (`review` / `other`), not by piping the recipe to grep — two defects caught before it shipped: `printf '%s' ""` gives grep no line to match, so the first version silenced exactly the default case, and a `//` default read a numeric or object recipe as review and counted a round.

### Changed

- **The triage policy is injected in full once per session and mode; later triggers carry a one-line pointer.** `scope-review-triage.sh` fires on every review entry, companion pass and review-type subagent dispatch — 25 times in one measured session — and repeated the ~450-character policy verbatim each time. The hook now keeps a flag under `$TMPDIR` (`claude-scope-triage-<session>`) holding the mode whose policy last went out in full; a later call in that session sends the head line, a pointer to the skill's Triage policy section, and the sentences that depend on state and must go out every time (round count, convergence warning, harvest check-in, the `init` pointer when there is no usable ledger, open HIGH follow-ups). A ledger that changes mode gets the other mode's text in full once more. `scope-session-start.sh` removes the flag on startup, resume, compact and clear, because that context no longer holds the earlier text. A flag path that is a symlink is never written through (the policy then goes out in full every time) and never removed. The flag is written after the policy is on stdout, so a flag can only exist once the full text has actually been emitted (the self-review found no reachable failure between the two in the current code; the order is kept because it makes that true by construction).

### Tests

## [1.0.2] - 2026-10-07

### Fixed

- **Malformed lines in the follow-ups file and the ledger are no longer swallowed silently; one parser defines the grammar.** The hooks decided "what is an open item" with their own one-line `grep`/`awk` patterns, so a subtly wrong line (`HIGH` glued to the next character, a missing `去處:`) was counted, dropped or both depending on the hook — and a separate audit of the same file with a stricter grammar (Pi's `parseFollowups` rejects the whole file on one bad line) showed two such lines nobody had noticed. The grammar now lives in `hooks/scope-parse.awk`; `_ledger.sh` reads through it, so its public functions keep their names and output. SessionStart lists each problem in either file as `line N: reason` with fixed wording only (never the line's text, so file content is not replayed into context); the first-prompt reminder repeats the follow-ups problems too, but only when the project has no usable ledger, and never reports ledger problems. A line whose checkbox, date and severity are right but whose `← from:` / `來源:` / `去處:` part is missing is still counted and flagged; an unrecognisable line is not counted, listed, and marked when it is an unticked line. Accepted for compatibility with the Pi version: `|` for `｜`, `source:` / `where:`, a trailing `<!-- scope:… -->` metadata comment (only the last one on a line is stripped, so text that quotes the marker keeps its fields and a line that starts with one is reported rather than vanishing), and a UTF-8 byte order mark on line 1. A Deferred value that itself contains `｜` or `|` is cut in two by the separator; the parser now says so instead of truncating it silently (Pi would reject the whole file).
- **The parser runs in linear time and in bytes.** The pre-push security review found the first version quadratic: regexes that began with an unanchored `[ ]*`, a right-trim done with `sub(/[ ]+$/)` and a last-occurrence search that re-copied the string on every step. Under BSD awk (macOS's default) a 50KB line of blanks took 12 seconds, past the hook's 10-second timeout, and SessionStart parses the ledger nine times; under gawk a 1MB line of repeated markers took 25 seconds. The old `grep` was linear, so this was a regression of the change itself, not inherited. Now: no leading `[ ]*` (every captured value is trimmed anyway), a right-trim that finds the last non-blank with one anchored match (a character loop was tried first and is itself quadratic on trailing blanks under BSD awk, because `substr()`/`length()` re-measure the string on every call), and a `split()`-based last-occurrence search with one extra look for an overlapping match. The parser also runs with `LC_ALL=C`: BSD awk in a UTF-8 locale aborts the whole run with `towc: multibyte conversion failure` when a regex meets a line it cut mid-character (a follow-up with no date followed by Chinese text), which silently dropped that line and every line after it — the failure this change exists to remove. A hook that outlives its timeout is killed together with its awk children on macOS/Linux (reported by the reviewer from the Claude Code binary and an experiment; Windows not checked).
- **The ledger reports the mistakes that used to make work disappear.** Found by Codex's review of the pull request (three P2 comments, each reproduced before acting on it): a frontmatter line without its colon (`mode harvest`) was ignored and `mode` fell back to `converge` while the notice said the file was clean; a section heading with the wrong case (`## In Scope`) made every checklist line under it vanish, so the Stop hook let a session end with open work; and, a regression of this change, `followups_high | head -5` in SessionStart killed the reader's awk with SIGPIPE once the output passed a pipe buffer (10,000 HIGH entries), so the hook exited before printing the format notice — the old `grep` readers absorbed that with `|| true`. Now reported: a frontmatter line that is not `key: value` (blank lines, `#` comments and indented continuations are fine), a missing `mode`, a heading that differs from `In scope` / `Deferred` / `Log` only by case or blanks, a checklist under an unknown section (flagged as unticked when it is), and a missing `## In scope`; every reader function ends in `|| true`. Tests written first and seen red; seven more mutations turned the suite red, including one for the second `head` user (`ledger_section … | head -10`) that had no test at first. A differential run of 4,149 inputs on BSD awk and gawk showed every non-`X` record identical to the previous version and no problem record lost; only new warnings appear.
- **A second Codex pass, on the fixes above, found six more cases of the same kind; all were reproduced and fixed.** A CRLF ledger had its `harvest` mode silently flipped to `converge` by the counted-round rewrite (the same first-line fence defect as the BOM one; the rewrite now ignores the CR, keeps the file's line endings and, because its CR-stripping regex aborts BSD awk on invalid UTF-8 in a UTF-8 locale, runs with `LC_ALL=C` — a guard that had been dropped as untested and that the new UTF-8 test then showed was needed); a duplicated frontmatter field was validated on its last value while the reader used its first, so an invalid first `mode` passed as clean (now the first is validated and the duplicate is reported); an empty ledger, which the edit gate treats as usable, produced no notice at all; in an unknown section a ticked checklist line used up the warning that was meant for the unticked one after it; `review_rounds: 08` was octal to bash arithmetic and made the review hook die after taking its lock (`ledger_rounds` now returns a canonical decimal); and an item with no text (`- [ ]  ← 來源: user`) was a clean open blank task that the Stop hook kept blocking on. Tests first, seen red; ten more mutations turned the suite red, one of which (the CR on the line inserted before the closing fence) survived until a CRLF ledger without a `review_rounds` key was added. The differential run against the previous parser again shows every non-`X` record identical on 4,149 inputs, and no problem record lost.
- **A third Codex pass found four more, two of them P2; all were checked and fixed.** An unticked item whose checkbox spacing was wrong (`- [ ]2026-… HIGH …`, `- [ ]item`) was marked `open=0`, so it was neither counted nor flagged as pending (the checkbox character is known to be a blank, so it is unticked); the README's own ledger template writes `← source:`, `severity:`, `why:` and `where:`, which the parser did not recognise, so anyone who copied it got a warning on every item — the template predates this change and the old hooks never looked at labels, so the parser now accepts those names, as it already did for follow-ups; the notice counted problem records as lines (a frontmatter missing both `goal` and `mode` is one line, two records) and now counts distinct lines and says how many records it left out of the list; and the README presented one assertion total as the size of the suite although it depends on how many awks the machine has. The differential run against the previous parser showed 224 of 4,149 inputs with a changed non-`X` record, every one of them containing the alias or checkbox forms changed on purpose and none unexplained; the two real files are unaffected. Seven more mutations turned the suite red; one (the condition that decides whether to print the "rest" line) survived until an input with more records than lines was added.
- **A fourth Codex pass (two P2, down from six) found two more; both were reproduced and fixed.** A frontmatter value with trailing blanks (`mode: harvest `, `review_rounds: 7 `) passed the validator, which trimmed it, but the reader consumed it verbatim: `mode` read as `converge` and `ledger_rounds` returned 0, so the next counted review silently reset the counter to 1 — with a notice that said the file was clean. The parser now hands the readers the trimmed value, which is the one it validated. And a Deferred item whose `← 來源:` has no value was a clean record (In scope and follow-ups already warned); it is reported now. Tests first, seen red; two more mutations turned the suite red; the differential run shows no other non-`X` record changed on 4,149 inputs.
- **`ledger_bump_rounds` no longer turns a `harvest` ledger into `converge` when the file starts with a UTF-8 BOM.** Found by the independent review of this change; the defect predates it. The BOM hid the opening `---`, so a second frontmatter block was synthesised in front of the real one and `mode` silently fell back to `converge` on the first counted review. The check and the rewrite now ignore the BOM and drop it.
- `skills/scope/SKILL.md`: the follow-ups `去處` list now matches what `defer`/`done` can write (`follow-ups` and `review-notes` were accepted by `defer` but missing from the follow-ups format).

### Tests

- 143 new assertions (440 total with a single awk installed; the parser cases repeat for every awk found, so CI reports more): the parser tested directly on every `awk` on the machine, hook-level cases for both files, a ledger with Pi metadata, a no-header file whose first line is an entry, a 6000-line ledger under `pipefail`, and — after an independent review round (five findings, each verified by a separate opus reviewer) — mid-line and leading metadata comments, a severity at end of line, ASCII `|` separators in Deferred, a missing `goal`, a `|` inside a Deferred value, and a UTF-8 BOM on the follow-ups header, the ledger frontmatter and the counted-round rewrite; then, after the pre-push security review, four timing tests capped at 10 seconds (a 120,000-blank run inside a follow-ups line and inside a Deferred line, about 1MB of repeated metadata markers, about 1MB of repeated `← 來源:`) plus one that the long-blank line still parses to complete fields. The BOM tests run under `LC_ALL=C`: BSD awk in a UTF-8 locale ignores a BOM when comparing strings, which made the unfixed code pass on the author's machine and let one mutation survive until the test was made locale-independent. Fifty-three mutations of a copy, each aimed at the collection layer, the wiring or the classification rather than at fixture data, each turned the suite red (parser off, severity ignored by the HIGH count, notice silenced in each of the three hooks, metadata not stripped, unrecognisable line counted, unticked flag wrong, header line swallowing the first entry, reason text leaking the line, recognised-but-incomplete lines not counted). One mutation survived the first round (the no-header case) and one test turned out not to protect what it claimed (the SIGPIPE one: `scope_parse`'s `|| true` and the readers' full read are independent guards, so only removing both turns it red); both were corrected and the second is documented in `_ledger.sh`.
- A second review, of the performance fix itself (4,149 generated inputs plus the two real files, 33,192 runs of the pre-fix parser against the new one on BSD awk and gawk in UTF-8 and C locales), found that the first fix was wrong in three ways, all corrected before anything shipped. Its character-loop right-trim was quadratic on blanks at the END of a line under BSD awk (1MB took 15 seconds; the old regex took 0.05). Replacing the last-occurrence search with `split()` changed which ` ← 來源: ` is found when two overlap (472 files differed, every one from this). And, present since the first commit, BSD awk in a UTF-8 locale aborted on a dateless line followed by Chinese text and dropped the rest of the file. Fixed with an anchored-match right-trim (preserving `RSTART`/`RLENGTH`, which `followup()` reads after `trim()`), one extra overlap check, and `LC_ALL=C` for the parser; the same differential run then showed zero differences from the first commit in all four configurations. Before that run this change had claimed that only performance changed, which was untrue. Tests added first and seen red: trailing blanks (3), overlapping markers (3), the UTF-8-locale abort (2), plus a UTF-8-locale check of the counted-round rewrite. Five more mutations turned the suite red; one survived (removing `LC_ALL=C` from the small awk filters that read the parser's output), and an experiment on invalid UTF-8 in three locales showed those filters never needed it, so that guard was removed instead of left untested.
- Run on BSD awk (macOS) and gawk 5.3.2 (the suite passes on both; a reviewer additionally compared 184 inputs across BSD awk and gawk 5.2.2–5.4.1 in UTF-8, C, `--posix` and `--traditional` modes with zero output differences). mawk, which no local machine has, is the awk CI's Ubuntu runner uses, and the CI run on this change (PR #9) executed the whole parser test family under `[mawk]` — the P, PL and PERF cases, including the BOM, overlapping-marker and timing ones — and passed. The parser avoids `{n}` intervals, multibyte characters inside bracket expressions and gawk-only functions for that reason. The test loop skips an awk that is not installed without saying so, which is why the CI log was searched for `[mawk]` lines instead of trusting a green check.

## [1.0.1] - 2026-09-23

### Fixed

- **A review command the user types now counts as a round.** `review_rounds` was bumped only by the PostToolUse `Skill` hook. A typed slash command is expanded inline and never becomes a Skill tool call, so every typed review went uncounted — including every `/claude-security` run, which is `disable-model-invocation` and can only be typed. Its allowlist entry could never match. In use, a ledger read round 4 while its Log recorded five reviews: two runs were typed `/claude-security`. `scope-review-triage.sh` is now also wired to `UserPromptSubmit`. Prose that mentions a command, a command on the second line, and non-review commands stay silent. The allowlist also accepts the fully qualified `claude-security:claude-security`. The harness hands `UserPromptSubmit` the raw submitted text (checked against the 2.1.280 binary: hooks receive the pre-expansion input). 18 new assertions (297 total), with two inputs per branch; `R11f` replays the reported mix of three Skill-route and two typed rounds and expects 5.

## [1.0.0] - 2026-09-23

### Added

- Initial release — a **per-goal** scope ledger (`.claude/scope-ledger.local.md`: goal verbatim, `mode` converge|harvest, `opened_on` branch as a record only, `review_rounds`, In scope / Deferred / Log), a per-repository follow-ups backlog (`.claude/scope-followups.local.md`), and six fail-open bash hooks:
  - `scope-gate.sh` (PreToolUse `Edit|Write|MultiEdit|NotebookEdit`) — the main thread's first edit of a source file in the project's git worktree, when the project has no ledger, is denied once with a message asking for `/scope-ledger:scope init`; the retry passes. The branch does not matter. Subagent edits (hook input carries `agent_id`) pass without touching the session flag — a subagent has no user request to write a goal from, and consuming the flag would leave the main thread ungated. `.claude/`, `openspec/`, non-source files and paths outside the project are exempt. Same batch-window and session-flag mechanics as `openspec-superpowers-workflow`'s skip-gate.
  - `scope-gate-bash.sh` (PreToolUse `Bash`) — the same verdict for source files written through the shell: after heredoc bodies and single-quoted strings are dropped, the token after `>`/`>>`, `tee`'s file, the file operands of `sed -i`/`perl -pi`, the last operand of `cp`/`mv`, and `git apply`/`patch` are each judged as a write target. Reads, `$TMPDIR`/`/tmp`, `.claude/` and outside-project paths never trigger it. Both gates share one session flag.
  - `scope-prompt-reminder.sh` (UserPromptSubmit) — once per session, on the first prompt a person types (harness wake-ups skipped): if the project has no usable ledger, one non-blocking line says so, points at `init`, and reports open follow-ups (HIGH first).
  - `scope-review-triage.sh` (PostToolUse `Skill|Agent`) — a Skill call on the review-entry allowlist (`review-branch`, `review-pr`, `security-review`, `claude-security`, `security-audit`, `code-review`, `simplify`, `debate`, `high-precision-dev:start`, `engineering:code-review`; extend with one regex per line in `~/.claude/scope-ledger-review-patterns`) increments `review_rounds` and injects the mode's triage policy. The Codex companion pass (`codex-review-bg`, `codex:review`, `codex:adversarial-review`) and review-type Agent dispatches inject without counting. Converge mode: findings are input, not a work order — adopt what belongs to this change, plus an exploitable security finding in the touched code, another instance of the same defect, a project MUST rule, or a boy-scout fix; defer the rest with severity, reason and destination (a HIGH security item only to an issue or the next goal); dismiss only with a counter-evidence anchor; warning from round 3. Harvest mode: findings are the work, batched by severity; status check-in every fifth round. Open HIGH follow-ups are mentioned.
  - `scope-stop-check.sh` (Stop) — blocks once per distinct open-item state while In scope has unticked items, listing them and asking for a per-item status; it defers to the user's last instruction on whether work continues and never asks for new work itself. `stop_hook_active` always passes.
  - `scope-session-start.sh` (SessionStart `startup|resume|compact|clear`) — prints the frontmatter, the whole In scope section, the Deferred and Log counts and the round count into the new context, then the open follow-ups (HIGH first), which are announced even when no ledger exists.
- `/scope-ledger:scope` skill — `init "<goal>"` (decides the mode, offers open follow-ups for pickup, reports git-ignore status with all three `check-ignore` exit codes handled and names the exact `.gitignore` line without editing it), `status`, `defer "<item>" --severity … --why … --to …`, `done` (refuses open items and destination-less deferrals, moves Deferred into the follow-ups file, writes a narrative memory entry, removes the ledger).
- `tests/scope-hooks.test.sh` — 279 assertions, two inputs per branch, green under bash 5, macOS bash 3.2, a pure BSD userland, and with `TMPDIR` unset (fixtures under `/tmp`, as on CI); wired into CI. Twenty-two mutations of a copy each verified red before release.

### Notes — what the pre-release reviews changed

The first draft went through the repo's own review chain (`/review-branch` with five adversarial verifier subagents, plus a Codex cross-vendor pass, then the pre-push security review), and then a second, deliberately broader review against the author's own session history — "does this make work converge without letting real bugs or security findings be skipped?". Everything below was changed before 1.0.0 shipped, so none of it is a released bug; it is recorded because each one is a design decision the next reader should not have to rediscover.

**Second round (policy and coverage, measured against the session history):**

- **A ledger is per goal, not per branch.** The first draft bound the ledger to a branch and denied edits on any other branch. Nine of thirteen long sessions in the history switch branches three or more times (one session 31 times) — hotfixes, PR chains, Dependabot batches — under one goal, and seventeen PRs spawned by one goal is exactly the expansion the ledger exists to make visible. `branch:` became `opened_on:` (a record), and the gate only asks whether a ledger exists.
- **`mode: harvest` for goals that are themselves an audit or a batch of findings.** About a quarter of the history's sessions start from an audit-type request. Under the convergence rule alone every finding of a security audit would have been deferred — the "the ledger made me skip the fix" failure the plugin must not produce. In harvest mode findings are the work, batched by severity, with a status check-in every fifth round instead of a convergence warning.
- **Deferring is scheduling, not dismissal; the destination is a file that is looked at.** `done` used to write Deferred items into project memory, where the author's own follow-ups had already been forgotten once. They now go to `.claude/scope-followups.local.md`, announced by SessionStart, the first-prompt reminder and `status` (HIGH first), offered by `init` for pickup; a HIGH security item cannot be deferred without an issue number or the next goal.
- **Four explicit adoption exceptions in converge mode** — an exploitable security finding in the touched code, another instance of the same defect (sibling), a project MUST rule, a boy-scout fix — and a counter-evidence requirement for won't-fix, so the convergence rule cannot be used to wave away a real problem.
- **A Bash write gate.** The harness's auto mode steers the model toward `sed -i`, `perl -pi` and heredoc redirects, which the Edit gate never sees; the history has hundreds of such writes. Without it the plugin was silent in exactly those sessions. Plus a once-per-session first-prompt reminder for sessions whose edits take neither path.
- **The Stop message no longer offers "keep working" as its first option.** The author had once told a session to pause all agents; a Stop-hook directive must not override that. It now asks for a per-item status and defers to the user's last instruction.
- **"Tracked" also survives case folding** (second pre-push security review, Medium, reproduced on APFS). A repository that commits `.Claude/scope-ledger.local.md` — or `.Claude/scope-followups.local.md`, whose HIGH lines SessionStart now prints — puts a real file at the lower-case path on a case-insensitive filesystem, while `git ls-files` with a case-sensitive pathspec reports nothing; every hook accepted it, SessionStart replayed it, Stop quoted it, the triage hook wrote into it. Both index lookups now use the `:(icase)` pathspec (`H14g`–`H14m`). On a case-sensitive filesystem that can only err toward ignoring a ledger. The same review noted the three per-session files under `$TMPDIR` were written without a symlink check; a planted symlink on a shared `/tmp` could make the hook create or truncate another path — each write now refuses a symlinked flag or state file (`G13`).
- **The Bash gate has no blanket `/tmp` exemption** (caught by CI, not by any local run). The first version skipped every write target under `/tmp`, meant for scratch files; on the CI runner `TMPDIR` is unset, the fixture projects live under `/tmp`, and every deny case went green locally (macOS `$TMPDIR` is under `/var/folders`) and red on ubuntu — the gate was a no-op for any project that itself lives under `/tmp`. A target outside the project already passes, and `$TMPDIR` targets arrive unexpanded and are dropped, so the exemption was both redundant and wrong; `B11` runs a project under `/tmp`.
- **The Bash gate keeps what follows a heredoc delimiter** (Codex cross-vendor pass on this round). `cat <<'EOF' > src/new.ts` is valid bash; the first stripper printed only the text before `<<`, so the redirect after the delimiter was never seen and the write slipped through. Only the `<<DELIM` token and the body are removed now; `B10` covers both `> file` and `| tee file` after the delimiter. The same self-review pass had already fixed three false denies in that hook: `patch` matched anywhere in a segment (`npm version patch`), relative targets ignored a leading `cd <dir>`, and `$VAR` targets were judged as project files.
- **Stale locks are cleared.** A hook killed by its 10-second timeout left `review_rounds.lock` behind, after which every bump waited, gave up and the counter silently froze; a lock older than 30 seconds is now removed. `codex-review-bg` no longer counts as a round of its own (it accompanies `/review-branch`), and SessionStart prints the whole In scope list instead of the first 60 lines.

**First round:**

- **A git-tracked ledger is repository-controlled content** (Codex, P1). SessionStart replayed the file verbatim into context and Stop quoted its lines into the block reason — a prompt-injection channel for anyone who can commit a `.claude/scope-ledger.local.md`. Every hook now checks first and treats such a ledger as absent; SessionStart prints one fixed line instead.
- **…and "tracked" is a property of the path, not of one index entry** (pre-push `/security-review`, Medium, reproduced against all four hooks). The first version of that check only asked `git ls-files --error-unmatch` about the exact ledger path. A committed `.claude` **symlink** to a tracked directory, or `.claude` as a **submodule**, puts a real file at the ledger path after a plain clone with no index entry at that name — every hook accepted it as the user's own ledger, and the triage hook wrote `review_rounds` through the symlink into tracked content. The check now also refuses a symlinked `.claude`, a symlinked ledger file and a `.claude` index entry of mode `120000`/`160000`; `ledger_bump_rounds` refuses symlinked paths outright. Both layouts are fixtures (`H14`, `T6`).
- **Agent dispatches no longer count as review rounds** (verifier, confirmed by replay). `/review-pr` launches six agents, a security scan dozens; counting dispatches jumped the counter to 5 inside the first review and fired the round-3 warning on the second agent. Only allowlisted Skill calls count now; Agent dispatches get the policy only.
- **Review detection is an allowlist, not keyword stems** (verifier, 215 local names scanned). `review|security|codex|verif…` counted `superpowers:verification-before-completion` (called before every completion claim), `security-ci-setup`, `codex:setup`, `codex:status` and the `claude-security` scan sub-agents as reviews. A user-level patterns file extends the allowlist.
- **Subagents pass the gate without consuming the flag** (verifier, from the harness's own hook schema: `agent_id` is present only inside a subagent). Before, a delegated implementer's first edit ate the session's single deny — the main thread was never asked for a ledger — and an implementer with a Skill tool would have written a goal it could only invent.
- **`review_rounds` is bumped under a `mkdir` lock** (Codex, P2): two hooks finishing in one batch could both read N and write N+1.
- **A ledger with no frontmatter gets one synthesised** (verifier). The bump used to report "round 1" forever on such a file while never changing it.
- **Cross-repository edits are documented as outside the gate** (verifier, three combinations replayed): "the project" is the session's project directory by design; the README's limits now say so, along with the subagent and 60-line-replay limits.
- Under `set -u`, bash reads a full-width character glued to a bare variable name (`$ledger：`) as part of the name and aborts; every interpolation next to non-ASCII text in the hooks is `${var}` for that reason.
