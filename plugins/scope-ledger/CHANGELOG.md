# Changelog

All notable changes to the `scope-ledger` plugin will be documented in this file.

## [1.0.0] - 2026-09-23

### Added

- Initial release — a **per-goal** scope ledger (`.claude/scope-ledger.local.md`: goal verbatim, `mode` converge|harvest, `opened_on` branch as a record only, `review_rounds`, In scope / Deferred / Log), a per-repository follow-ups backlog (`.claude/scope-followups.local.md`), and six fail-open bash hooks:
  - `scope-gate.sh` (PreToolUse `Edit|Write|MultiEdit|NotebookEdit`) — the main thread's first edit of a source file in the project's git worktree, when the project has no ledger, is denied once with a message asking for `/scope-ledger:scope init`; the retry passes. The branch does not matter. Subagent edits (hook input carries `agent_id`) pass without touching the session flag — a subagent has no user request to write a goal from, and consuming the flag would leave the main thread ungated. `.claude/`, `openspec/`, non-source files and paths outside the project are exempt. Same batch-window and session-flag mechanics as `openspec-superpowers-workflow`'s skip-gate.
  - `scope-gate-bash.sh` (PreToolUse `Bash`) — the same verdict for source files written through the shell: after heredoc bodies and single-quoted strings are dropped, the token after `>`/`>>`, `tee`'s file, the file operands of `sed -i`/`perl -pi`, the last operand of `cp`/`mv`, and `git apply`/`patch` are each judged as a write target. Reads, `$TMPDIR`/`/tmp`, `.claude/` and outside-project paths never trigger it. Both gates share one session flag.
  - `scope-prompt-reminder.sh` (UserPromptSubmit) — once per session, on the first prompt a person types (harness wake-ups skipped): if the project has no usable ledger, one non-blocking line says so, points at `init`, and reports open follow-ups (HIGH first).
  - `scope-review-triage.sh` (PostToolUse `Skill|Agent`) — a Skill call on the review-entry allowlist (`review-branch`, `review-pr`, `security-review`, `claude-security`, `security-audit`, `code-review`, `simplify`, `debate`, `high-precision-dev:start`, `engineering:code-review`; extend with one regex per line in `~/.claude/scope-ledger-review-patterns`) increments `review_rounds` and injects the mode's triage policy. The Codex companion pass (`codex-review-bg`, `codex:review`, `codex:adversarial-review`) and review-type Agent dispatches inject without counting. Converge mode: findings are input, not a work order — adopt what belongs to this change, plus an exploitable security finding in the touched code, another instance of the same defect, a project MUST rule, or a boy-scout fix; defer the rest with severity, reason and destination (a HIGH security item only to an issue or the next goal); dismiss only with a counter-evidence anchor; warning from round 3. Harvest mode: findings are the work, batched by severity; status check-in every fifth round. Open HIGH follow-ups are mentioned.
  - `scope-stop-check.sh` (Stop) — blocks once per distinct open-item state while In scope has unticked items, listing them and asking for a per-item status; it defers to the user's last instruction on whether work continues and never asks for new work itself. `stop_hook_active` always passes.
  - `scope-session-start.sh` (SessionStart `startup|resume|compact|clear`) — prints the frontmatter, the whole In scope section, the Deferred and Log counts and the round count into the new context, then the open follow-ups (HIGH first), which are announced even when no ledger exists.
- `/scope-ledger:scope` skill — `init "<goal>"` (decides the mode, offers open follow-ups for pickup, reports git-ignore status with all three `check-ignore` exit codes handled and names the exact `.gitignore` line without editing it), `status`, `defer "<item>" --severity … --why … --to …`, `done` (refuses open items and destination-less deferrals, moves Deferred into the follow-ups file, writes a narrative memory entry, removes the ledger).
- `tests/scope-hooks.test.sh` — 279 assertions, two inputs per branch, green under bash 5, macOS bash 3.2, a pure BSD userland, and with `TMPDIR` unset (fixtures under `/tmp`, as on CI); wired into CI. Twenty-two mutations of a copy each verified red before release.

### Notes — what the pre-release reviews changed

The first draft went through the repo's own review chain (`/review-branch` with five adversarial verifier subagents, plus a Codex cross-vendor pass, then the pre-push security review), and then a second, deliberately broader review against the author's own session history — "does this make work converge without letting real bugs or security findings be skipped?". Everything below was changed before 1.0.0 shipped, so none of it is a released bug; it is recorded because each one is a design decision the next reader should not have to rediscover.

**Second round (policy and coverage, measured against the session history):**

- **A ledger is per goal, not per branch.** The first draft bound the ledger to a branch and denied edits on any other branch. Nine of thirteen long sessions in the history switch branches three or more times (one session 31 times) — hotfixes, PR chains, Dependabot batches — under one goal, and seventeen PRs spawned by one goal is exactly the expansion the ledger exists to make visible. `branch:` became `opened_on:` (a record), and the gate only asks whether a ledger exists.
- **`mode: harvest` for goals that are themselves an audit or a batch of findings.** About a quarter of the history's sessions start from an audit-type request. Under the convergence rule alone every finding of a security audit would have been deferred — the "the ledger made me skip the fix" failure the plugin must not produce. In harvest mode findings are the work, batched by severity, with a status check-in every fifth round instead of a convergence warning.
- **Deferring is scheduling, not dismissal; the destination is a file that is looked at.** `done` used to write Deferred items into project memory, where the author's own follow-ups had already been forgotten once. They now go to `.claude/scope-followups.local.md`, announced by SessionStart, the first-prompt reminder and `status` (HIGH first), offered by `init` for pickup; a HIGH security item cannot be deferred without an issue number or the next goal.
- **Four explicit adoption exceptions in converge mode** — an exploitable security finding in the touched code, another instance of the same defect (sibling), a project MUST rule, a boy-scout fix — and a counter-evidence requirement for won't-fix, so the convergence rule cannot be used to wave away a real problem.
- **A Bash write gate.** The harness's auto mode steers the model toward `sed -i`, `perl -pi` and heredoc redirects, which the Edit gate never sees; the history has hundreds of such writes. Without it the plugin was silent in exactly those sessions. Plus a once-per-session first-prompt reminder for sessions whose edits take neither path.
- **The Stop message no longer offers "keep working" as its first option.** The author had once told a session to pause all agents; a Stop-hook directive must not override that. It now asks for a per-item status and defers to the user's last instruction.
- **"Tracked" also survives case folding** (second pre-push security review, Medium, reproduced on APFS). A repository that commits `.Claude/scope-ledger.local.md` — or `.Claude/scope-followups.local.md`, whose HIGH lines SessionStart now prints — puts a real file at the lower-case path on a case-insensitive filesystem, while `git ls-files` with a case-sensitive pathspec reports nothing; every hook accepted it, SessionStart replayed it, Stop quoted it, the triage hook wrote into it. Both index lookups now use the `:(icase)` pathspec (`H14g`–`H14m`). On a case-sensitive filesystem that can only err toward ignoring a ledger. The same review noted the three per-session files under `$TMPDIR` were written without a symlink check; a planted symlink on a shared `/tmp` could make the hook create or truncate another path — each write now refuses a symlinked flag or state file (`G13`).
- **The Bash gate has no blanket `/tmp` exemption** (caught by CI, not by any local run). The first version skipped every write target under `/tmp`, meant for scratch files; on the CI runner `TMPDIR` is unset, the fixture projects live under `/tmp`, and every deny case went green locally (macOS `$TMPDIR` is under `/var/folders`) and red on ubuntu — the gate was a no-op for any project that itself lives under `/tmp`. A target outside the project already passes, and `$TMPDIR` targets arrive unexpanded and are dropped, so the exemption was both redundant and wrong; `B11` runs a project under `/tmp`.
- **The Bash gate keeps what follows a heredoc delimiter** (Codex cross-vendor pass on this round). `cat <<'EOF' > src/new.ts` is valid bash; the first stripper printed only the text before `<<`, so the redirect after the delimiter was never seen and the write slipped through. Only the `<<DELIM` token and the body are removed now; `B10` covers both `> file` and `| tee file` after the delimiter. The same self-review pass had already fixed three false denies in that hook: `patch` matched anywhere in a segment (`npm version patch`), relative targets ignored a leading `cd <dir>`, and `$VAR` targets were judged as project files.
- **Stale locks are cleared.** A hook killed by its 10-second timeout left `review_rounds.lock` behind, after which every bump waited, gave up and the counter silently froze; a lock older than 30 seconds is now removed. `codex-review-bg` no longer counts as a round of its own (it accompanies `/review-branch`), and SessionStart prints the whole In scope list instead of the first 60 lines.

**First round:**

- **A git-tracked ledger is repository-controlled content** (Codex, P1). SessionStart replayed the file verbatim into context and Stop quoted its lines into the block reason — a prompt-injection channel for anyone who can commit a `.claude/scope-ledger.local.md`. Every hook now checks first and treats such a ledger as absent; SessionStart prints one fixed line instead.
- **…and "tracked" is a property of the path, not of one index entry** (pre-push `/security-review`, Medium, reproduced against all four hooks). The first version of that check only asked `git ls-files --error-unmatch` about the exact ledger path. A committed `.claude` **symlink** to a tracked directory, or `.claude` as a **submodule**, puts a real file at the ledger path after a plain clone with no index entry at that name — every hook accepted it as the user's own ledger, and the triage hook wrote `review_rounds` through the symlink into tracked content. The check now also refuses a symlinked `.claude`, a symlinked ledger file and a `.claude` index entry of mode `120000`/`160000`; `ledger_bump_rounds` refuses symlinked paths outright. Both layouts are fixtures (`H14`, `T6`).
- **Agent dispatches no longer count as review rounds** (verifier, confirmed by replay). `/review-pr` launches six agents, a security scan dozens; counting dispatches jumped the counter to 5 inside the first review and fired the round-3 warning on the second agent. Only allowlisted Skill calls count now; Agent dispatches get the policy only.
- **Review detection is an allowlist, not keyword stems** (verifier, 215 local names scanned). `review|security|codex|verif…` counted `superpowers:verification-before-completion` (called before every completion claim), `security-ci-setup`, `codex:setup`, `codex:status` and the `claude-security` scan sub-agents as reviews. A user-level patterns file extends the allowlist.
- **Subagents pass the gate without consuming the flag** (verifier, from the harness's own hook schema: `agent_id` is present only inside a subagent). Before, a delegated implementer's first edit ate the session's single deny — the main thread was never asked for a ledger — and an implementer with a Skill tool would have written a goal it could only invent.
- **`review_rounds` is bumped under a `mkdir` lock** (Codex, P2): two hooks finishing in one batch could both read N and write N+1.
- **A ledger with no frontmatter gets one synthesised** (verifier). The bump used to report "round 1" forever on such a file while never changing it.
- **Cross-repository edits are documented as outside the gate** (verifier, three combinations replayed): "the project" is the session's project directory by design; the README's limits now say so, along with the subagent and 60-line-replay limits.
- Under `set -u`, bash reads a full-width character glued to a bare variable name (`$ledger：`) as part of the name and aborts; every interpolation next to non-ASCII text in the hooks is `${var}` for that reason.
