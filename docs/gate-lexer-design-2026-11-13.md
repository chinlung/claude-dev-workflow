# gate tokenizer 合成單一 lexer 設計（W5-8，2026-11-13）

> 狀態：使用者 2026-11-13 核准，§8 三點照建議（D1 分兩步、D2 字元層級生成語法先做、D3 上線前送 codex 與 `/security-review`）。第一步已實作，結果與偏離設計之處見 §10。

> 前置：PR #55（兩份對齊）、#57（differential harness、註解規則、每條命令讀兩次取聯集）。

## 1. 為什麼要做

共用區段現在有**兩個掃描器**：heredoc pass 逐行找 heredoc 本體，tokenizer 逐字切詞。兩者各自維護一份引號、`$'…'`、續行、註解的狀態，而且對「什麼是詞」的看法不同：

- heredoc pass 以「前一個字元是 `[\s;&|()]`」判斷 `#` 是不是註解；tokenizer 以「目前沒有打開的詞」判斷。
- 引號與 `$'…'` 的處理各寫一遍。
- `$( … )`、反引號、`${…}` 裡的內容靠 `subs_of` 另外切出來丟回佇列重掃，等於第三種解析。

這個結構讓每一個局部修補都有風險：PR #55 補替換掃描、PR #57 加註解規則，後者被各層審查找到六次退化（反引號內的註解、`${x:- #}`、引號被拆散、輪數耗盡、緊貼 `)` 的 `#`、`${x:-{}`），最後只能靠「每條命令讀兩次取聯集」兜底。聯集保證不退步，但解不掉下面三個既有缺口，它們都出在兩個掃描器的接縫上：

| 缺口 | 例子 | 現況 |
|---|---|---|
| 0 | `x=$(cat <<EOF⏎text⏎EOF)⏎openspec archive foo` | `EOF)` 被當成沒收尾，之後到某個 `EOF` 行之前的命令被吞掉 |
| 1 | `cat <<'E'"F"⏎it's⏎EF⏎openspec archive foo` | delimiter 只取到 `E`，本體當成沒收尾，本體裡的撇號開出字串 |
| 2 | `echo "x $(echo "a"; gh pr merge 3) y"` | 外層字串在內層引號處被截斷，後面的命令被當成文字 |

三個都是 main 本來就漏的（不是退化），而且都已用完整 hook 實測確認會放行。

## 2. bash 的事實（2026-11-13 實測，bash 3.2.57 與 5.3.20 一致）

以只放探針命令的 PATH、`env -i` 下執行，每個案例在兩個版本跑：

| 案例 | 結果（兩版本相同） |
|---|---|
| `x=$(cat <<EOF⏎text⏎EOF)⏎probe` | `EOF)` 結束 `$( … )`，heredoc 以替換的結尾收尾（5.3 多印一行警告）；`probe` 照常執行 |
| `x=$(cat <<EOF⏎text⏎EOF)⏎probe middle⏎cat <<EOF⏎body⏎EOF⏎probe end` | 三段命令都執行，沒有東西被吞掉 |
| `cat <<'E'"F"⏎it's $(probe)⏎EF⏎probe after` | delimiter 是相鄰各段拼起來的 `EF`，因為有引號所以本體不展開（`$(probe)` 是字面文字）；`probe after` 執行 |
| `cat <<"E"F …` | 同上：只要任一段有引號，本體就不展開 |
| `echo "x $(echo "a"; probe) y"` | `$( … )` 內是全新的引號脈絡，內層 `"a"` 不結束外層字串；`probe` 執行 |
| ``echo "x `echo \"a\"; probe` y"`` | 同上，反引號版 |

結論：三個缺口在 bash 兩個版本上都是**確定的行為**，可以精確建模，不需要「兩種都掃」的保守寫法。

實作時（§10）字元層級語法又帶出幾條，同樣在兩個版本實測：

| 案例 | 結果 |
|---|---|
| `echo $(( '`probe`' + 1 ))`、`echo $(( "$(probe)" + 1 ))` | 算術本體照「雙引號內、但引號本身是普通字元」展開：單引號裡的反引號也會執行（兩版相同） |
| `x=$(( <<<=⏎probe⏎))` | 算術本體裡的一般命令不執行（兩版相同） |
| `echo $((echo A) )`、`echo $((echo C); (echo D))` | `$((` 只有在「關掉第一個 `(` 的 `)` 後面緊接 `)`」時才是算術，否則是 `$( (…) … )` 子殼；以 `))` 結尾不代表是算術（兩版相同，`((` 命令亦同） |
| `echo $[1<<2]` | 舊式算術，`<<` 是位移不是 heredoc（兩版相同） |
| `let x=1<<n && cat <<EOF⏎probe⏎EOF` | `<<n` 是 heredoc，等不到 `n` 時其後全部是本體，**一行都不執行**（兩版相同；bash 只印警告） |
| `cat <<\⏎EOF⏎$(probe)⏎EOF` | `\⏎` 是續行不是引號：delimiter 是未加引號的 `EOF`，本體會展開（兩版相同） |
| `echo ${⏎probe a⏎}`、`echo ${ x}` | **兩版不同**：3.2 是 bad substitution，5.3 把 `${ … }` 當成在目前 shell 執行的命令清單（5.3 新語法 `${ cmd; }`、`${\| cmd; }`）。lexer 採 5.3 的讀法（多抓不少抓） |

## 3. 設計

### 3.1 一個字元層級的 lexer

一次走過整條命令字串，維護一個脈絡堆疊，取代 heredoc pass、tokenizer 與 `subs_of` 的重掃：

| 脈絡 | 進入 | 離開 | 裡面 |
|---|---|---|---|
| command | 起點、`;` `&` `\|` `(` 換行、`$(` 內、反引號內 | 對應的結尾 | 切詞；`#` 在詞首是註解 |
| single | `'` | 下一個 `'` | 全部是字面 |
| double | `"` | 下一個未跳脫的 `"` | 字面，但 `$(`、`${`、反引號開出新的脈絡 |
| ansi-c | `$'` | 下一個未跳脫的 `'` | 字面，`\'` 不結束 |
| subst | `$(` | 配對的 `)` | 一個全新的 command 脈絡（它自己的引號、註解、heredoc） |
| backtick | `` ` `` | 下一個反引號 | 一個全新的 command 脈絡，註解到反引號為止 |
| param | `${` | 配對的 `}` | 一個詞的內部：`#`、引號、空白都不開啟東西；引號內的 `}` 不收尾；其中的 `$(`／反引號仍開出 subst／backtick，單引號內的不算 |
| arith | `$((`、`((`、`$[` | 配對的 `))`／`]`（`$((` 不以 `))` 收尾時改讀成 subst） | 位移 `<<` 不是 heredoc；引號是普通字元，其中的 `$(`、反引號、`${` 照樣開出新脈絡 |

subst 與 backtick 是**遞迴進入同一個 lexer**，不是切出字串再重掃。這就是缺口 2 的解：脈絡堆疊本來就知道內層引號屬於內層。

### 3.2 heredoc

遇到 `<<`（不在 `<<<`、算術、註解、引號裡）時，**把 delimiter 讀完整**：相鄰的未加引號、單引號、雙引號、反斜線段拼成 delimiter 字串，只要任一段有引號或反斜線，本體就標為「不展開」（缺口 1 的解）。記下「待讀本體」佇列。

在該行結束的換行處（續行與跨行引號都處理完之後）依序讀每個待讀本體，到整行等於 delimiter（`<<-` 容許前置 tab）為止。**在 subst／backtick 脈絡內，本體另外在 `)`／反引號處也收尾**：行首是 `DELIM` 而緊接 `)` 時，本體在那裡結束並關閉替換（缺口 0 的解，bash 3.2 與 5.3 行為一致）。讀不到收尾的 heredoc 照 bash：其後全部是本體，一行都不當命令（§2）。舊掃描器把這種行放回重掃，是因為它會把 `$((1<<n))` 的位移誤認成 heredoc；lexer 在 arith 脈絡裡不找 heredoc，所以不需要這條保守規則（第一步的聯集裡舊讀法仍會重掃）。

不展開的本體整段丟棄；會展開的本體交給 lexer 的 double 脈絡規則，只取其中的 `$( )` 與反引號。

### 3.3 輸出

lexer 回傳**命令清單**：每個命令是詞的陣列（引號已解開、`$'…'` 已解碼成現有的規則），來自最外層與所有內層的 subst／backtick／param 脈絡，攤平成一份。使用端的邏輯幾乎不動：

- archive-gate：命令位置判斷、`openspec archive`、`mv … changes/archive/…`。
- merge gate：`gh pr merge`、`gh api …/merge`。
- `bash -c '…'`、`sh -c`、`eval …` 的字串仍然丟回佇列、整條重新 lex（那是 shell 字串，不是同一個脈絡的內層），50 輪上限照舊。

### 3.4 不變條件

- **終止**：每一輪迴圈索引必定前進；脈絡堆疊深度上限 50（`$( … )` 與 `$(( … ))` 皆然）、總步數上限 3,000,000，每個迴圈看過的字元都計入（§10），超過視為無法讀（merge gate 印 `- - -` 拒絕，archive-gate 照其 fail-open 設計放行）。
- **不 die**：未結束的引號、`${`、`$(`、heredoc 一律視為字面或延伸到結尾，不拋例外（merge gate 解析失敗會拒絕、archive-gate 會放行，兩者都不該因輸入而走到那條路）。
- **不比現在少抓**：見 §4 的上線方式。

### 3.5 程式放哪

仍是兩個 plugin 各一份、以 `# >>> shared-tokenizer:` 標記界定、由 `shared-tokenizer.test.sh` 比對一致（兩個 plugin 分開安裝，不能互相 source）。lexer 大約 120–160 行 Perl，取代現在的兩個掃描器加 `subs_of`，淨增減預期在 ±0 到 +40 行之間。

## 4. 上線方式：兩步

直接把兩個舊掃描器換掉，等於把「新規則只能多抓」這個保險拿掉，而這個保險正是 #57 付了六輪才換來的。所以分兩步，用同一個機器化的檢查決定何時可以拿掉舊的：

1. **第一步：lexer 當作第三種讀法加入聯集**。現有的兩種讀法（新規則、`$plain`）不動，每條命令多一個 lexer 的讀法，結果取聯集。這一步保證不退步、能抓到三個缺口、可以逐步累積證據。
2. **第二步：退役舊讀法**。條件是 §5 的超集檢查在「只剩 lexer」時仍然零遺漏。條件不成立就不退役，舊讀法留著當保險，並把差異列為新的缺口。這一步才真正完成「合成單一」，也是程式碼變少的地方。

第一步完成時，三個 `--gap` 檢查會轉紅（缺口被修好），依 suite 自己的設計把它們移回預設語法。

## 5. 驗收

全部機器化，由 CI 執行，不靠人讀：

1. **對 bash**：differential harness 在預設語法加入三個缺口後，8 個以上 seed × 兩支 gate × 400 案例零反例。
2. **不比舊版少抓**：`--superset-of` 對 `b81dcdc` 與對 `01457c3`（目前 main）都零遺漏。對 `01457c3` 是新增的檢查：目前的聯集版本是「現在」，lexer 不可以比它少。
3. **找得到新類別**：harness 新增字元層級的生成語法（引號、`#`、反斜線、`<<`、`$(`、`((`、`${`、換行、`;` 的隨機組合，bash 拒絕的語法自然在 `next unless @calls` 被濾掉）。這是 §1 提到「手寫語法只會重組已知形狀」的對策，也是重寫解析器最需要的證據：lexer 通過的是它沒看過的輸入。
4. **mutant**：兩支 suite 現有的 mutant 全部仍被「指定的案例」第一個殺掉；lexer 每個脈絡與規則（§3.1 的八種、heredoc 的三條規則）各至少一個 mutant。
5. **一致性**：`shared-tokenizer.test.sh` 對兩份 lexer 綠燈。
6. 既有的 `archive-gate`、`pr-merge-gate` 兩支 suite 的全部案例不改預期值（除了被刻意移回預設語法的缺口案例）。

## 6. 替代方案

| 方案 | 為什麼不選 |
|---|---|
| **B. 只針對三個缺口各補一條局部規則** | 成本最低，但就是 #57 走過的路：每條局部規則都有 bash 不同意的情境，要靠下一輪審查才發現。三個缺口出在兩個掃描器的接縫，補在接縫上只會增加接縫的複雜度 |
| **C. 換成真正的 shell parser（`shfmt --to-json`、bash 自己的 `bash -n` 搭配 declare）** | 多一個執行期依賴，而閘門必須決定它不存在時要 fail-open 還是 fail-closed；archive-gate 與 merge gate 的答案不同，且 plugin 安裝後不保證機器上有。perl 是兩支 hook 本來就要求的 |
| **D. 呼叫 bash 本身做 oracle**（在 hook 裡 `bash -n` 或用 `set -x` 的展開結果） | hook 不能執行使用者的命令，`bash -n` 只做語法檢查、不回報會執行什麼；harness 能用 bash 當 oracle 是因為它在 stub 的環境裡真的執行 |
| **E. 直接換掉舊掃描器、不經第一步** | 拿掉聯集這道保險，且沒有證據判斷 lexer 是否真的不比舊版少抓。第二步的條件就是補這個證據 |

## 7. 風險與不做的事

- **merge gate 是 fail-closed，archive-gate 是 fail-open**：lexer 的錯誤對兩者的後果不同。第一步用聯集，錯誤只會多抓或不改變結果，風險最低；風險集中在第二步，所以第二步有機器化的退役條件。
- **字元層級生成語法會找出新的缺口**：這是目的，不是風險；找到的照「findings stay findings」進帳本、不為了驗收放寬性質。但這可能讓第一步的 PR 帶出比預期更多的新缺口，範圍要在設計核准時講清楚（見 §8 D2）。
- **不做**：改 hooks.json 的 `if` 前置過濾；改兩支 gate 的命令位置規則、`gh api`／MCP merge 的判斷；處理 `bash <<EOF`、`… | bash`、alias、變數裡的命令（README 已明列不在覆蓋面內）；把 lexer 抽成獨立檔（仍在 follow-ups，要等兩個 plugin 的安裝方式有共用機制）。

## 9. 實作順序（核准後）

1. 字元層級生成語法加進 harness（D2），對現有 gate 跑，缺口進帳本。
2. lexer 寫在 harness 的測試環境裡（獨立的 `.pl`），先對 bash 跑到零反例，還不碰兩支 hook。
3. 把 lexer 放進兩支 hook 的共用區段當第三種讀法，三個 `--gap` 移回預設語法，補 mutant 與案例。
4. 自審一輪（簡化、review-branch、codex、`/security-review`），PR。
5. 第二步（退役舊讀法）：另開工作線，以驗收 2 的超集檢查決定。

## 10. 第一步的結果（2026-11-13）

**做了什麼**：兩支 gate 新增 `# >>> shared-tokenizer: lexer` 區段（約 180 行，比 §3.5 估的 120–160 多，兩份逐位元組相同），讀法迴圈改成 `for my $mode (0, 1, 2)`，第三種讀法是 lexer。heredoc pass、tokenizer 與 `subs_of` 原封不動，所以這一步程式碼只增不減；減的部分在第二步。

**驗收（§5）實際結果**：

1. 對 bash：lexer 單獨（把迴圈改成只跑 `2` 的副本）在最終版本上兩支 gate 皆零反例——預設語法 6 seeds × 400 案例、`--chars` 16 seeds × 1500 案例，共 44 次執行。suite 固定跑預設語法 400 案例與 `--chars` 一個 seed。
2. 超集：完整 gate（三讀法聯集）對 `b81dcdc` 與 `01457c3` 都零遺漏。lexer 單獨對兩者的超集檢查屬第二步，尚未做。
3. 新類別：`--chars` 在 lexer 寫好前就對現有 gate 找到四類反例（續行、反引號內的引號、重導向黏在詞上、雙引號反引號裡的 heredoc），寫 lexer 時又找到算術本體裡的替換（含單引號裡的反引號）、`$((` 不是算術的情況、`$[`、`<<\⏎`、等不到收尾的 heredoc、delimiter 裡的 `${…}` 與反引號、永不收尾的引號。可建模的全部進了預設語法（harness 的 wrapper／noise），三個舊 `--gap` 移回預設語法。不可建模的一類成為新的 gap 0（見下）。
4. mutant：18 個 lexer mutant 全數被 bash 判定為漏抓。兩支 gate 既有的 mutant（archive-gate 15 個、merge gate 43＋1 個）全數仍由指定案例先殺掉。
5. 一致性：`shared-tokenizer.test.sh` 比對三個區段，新增 lexer 區段的行數地板與一個 canary。
6. 既有案例：預期值沒有改。

**偏離設計之處**：

- **lexer 的 mutant 放在 differential suite，不在兩支 gate suite**。在三讀法聯集裡，舊讀法會補抓 lexer 漏掉的多數形狀，mutant 會存活；改在「只剩 lexer」的副本上、由 bash 當裁判。同理，兩支 gate suite 的既有 mutant 改跑在「只剩兩種舊讀法」的副本上，否則會被 lexer 遮蔽。兩支 suite 末尾另加只有 lexer 讀得對的端到端案例（archive-gate 9 個、merge gate 8 個），排在最後，舊讀法副本上的 mutant 才會先停在自己的目標案例。
- **`${ cmd; }` 的版本差異**（§2）：原本結論「兩版行為一致」只對三個缺口成立。
- **兩處改成「兩種都讀」**，與 §2 結論「不需要保守寫法」不同，因為 bash 的判定依賴 lexer 不建模的東西：(a) `$(( … ))` 判定為算術時，本體另外當 `( … )` 命令讀一次——bash 找算術結尾時引號算數，本體裡沒收尾的 `'` 會讓它改讀成命令替換；(b) 永不收尾的引號，其後的文字另外當命令讀一次——bash 會丟棄判為語法錯誤的整行、從下一行繼續執行（兩版皆然），那一行上的引號從未開啟。兩者都只會多抓。
- **新的 gap 0：語法錯誤而被丟棄的行**。(b) 只涵蓋永不收尾的引號；被丟棄的行上若有 heredoc（`a=(-( <<EOF`）或之後才收尾的引號，三種讀法都會把後面的行當本體或字串，而 bash 照常執行。要知道 bash 會丟棄哪一行就得有 bash 的完整語法，這一步不做；以 `--gap 0` 釘住，進 follow-ups。harness 的「被丟棄那行上的引號」wrapper 在 `--chars` 下停用，因為後面的隨機文字可能把引號關上，就落回 gap 0。
- **harness 的歸屬競態**：bash 可能在它啟動的程序結束前就返回（在管線裡展開 heredoc 本體），那次呼叫會寫進下一個案例的紀錄，造成假反例。`run_bash` 改成讓 bash 在自己的 process group 執行、等整個 group 結束（最多 3 秒）才讀紀錄。
- **merge gate 的輸出欄位**：`--repo` 的值黏上帶換行的引號字串時，一行 `repo num sha` 被切成兩行，hook 是因為殘缺行的空 sha 欄位才碰巧擋下、理由也錯；MCP 的 `pullNumber` 不是數字時則原樣交給 `ready`。改在消費端（`while read`）規定號碼欄必須全是數字，否則記為 `-`（以「讀不出是哪個 repo 的哪個 PR」擋下），兩個產生端一起涵蓋。harness 也改成照 `read -r` 的方式讀這些行。這不在共用區段裡，archive-gate 沒有這種輸出格式。
- **時間有界**（simplify 審查找到）：上面兩處「兩種都讀」會巢狀疊加，20 層未收尾的 `"$(` 或 20 層 `$((` 要數秒、40 層要數小時，超過 hook 時限。改成每段獨立文字（替換內文、未收尾引號的後文、算術本體）以內容雜湊記住、只讀一次——同一段文字讀出的命令必然相同，跳過不會少抓；另設 3,000,000 步上限，超過即視為讀不完（merge gate 拒絕、archive-gate 照 fail-open 放行）。差分 suite 以 40 層的兩種形狀限時 5 秒驗證。§3.4 的終止條件因此多了「總步數」一項。
- **步數涵蓋每個迴圈**（commit 前 review-branch 與 codex 找到）：原本只有 `lex_cmd` 的主迴圈計步、深度上限也只在 `lex_cmd`，而 `lex_arith` 直接遞迴自己、`param_end` 對每個未收尾的 `${` 掃到文字結尾後只前進一個字元、`lex_text` 每次複製並雜湊整段文字，這些都不計。12,000 層已收尾的 `$((` 要 20 秒（`01457c3` 為 0.07 秒），超過 archive-gate 10 秒的 hook 時限；4,000 個未收尾的 `${a:-` 讓整個解析從 3.8 秒變 7.9 秒，逾時的門檻提早一半；merge gate 的解析又在 `ready` 的 25 秒預算起算之前。改成：一步是任何迴圈看過的一個字元，掃不到收尾的掃描與為了另讀而複製的文字每次都重新計入，超過上限就以 sentinel `die` 結束、`lex_segs` 接住並設 `$LEX_UNREAD`，保留已讀到的命令；`lex_arith` 入口也檢查深度 50。修正後兩種輸入分別在 0.1 秒與 0.5 秒內停下，960 KB 的 heredoc 0.26 秒讀完而不觸頂（上限約 2 秒的讀取量）。差分 suite 加了寬輸入的限時案例與三個 canary（拿掉記憶、拿掉 `param_end` 的計步、拿掉 `lex_arith` 的深度與計步），各自會失敗。舊兩種讀法本身對大量未收尾的 `${` 也是二次方（`01457c3` 上 4,000 個 3.8 秒），是既有問題，進 follow-ups，第二步退役舊讀法時一起消失。
- **預算是整條命令的**（merge 前補審的 review-branch 第 2 輪找到）：`lex_segs` 原本對每個佇列項目（命令本身與每個 `bash -c`、`sh -c`、`eval` 的命令字串，最多 50 個）都把步數歸零，上限實際是 50 × 3,000,000 步；50 段各帶 1,100 個未收尾 `${a:-` 的 `bash -c '…'` 讓 lexer 跑 18 秒、整個解析 33 秒，超過 merge gate 30 秒的時限。改成步數只在程式開頭歸零一次，用完後其餘項目第一步就停下（merge gate 擋）。修正後 lexer 0.5 秒、整個解析 15 秒，其餘是舊讀法（已在 follow-ups）。差分 suite 加了這個輸入的限時案例，以及恢復逐項歸零就逾時的 canary。

**第二步的起點**：lexer 單獨的副本已在 differential suite 每次執行；第二步要補的是 lexer 單獨對 `b81dcdc`、`01457c3` 的超集檢查，以及只有舊讀法抓得到、lexer 照 bash 不抓的形狀（例如等不到收尾的 heredoc 之後的行：舊讀法保守地當命令，bash 與 lexer 都不執行）——這類差異在 merge gate 的 fail-closed 下是誤擋，在第二步要逐一確認是舊讀法過度保守，而不是 lexer 漏讀。

## 11. 第二步的結果：試做、量測、不做（2026-11-13～14）

**結論**：兩種舊讀法不退役。§4 的規則是「條件不成立就不退役，舊讀法留著當保險」，量測結果是條件不成立，而且不是差幾條規則的問題。這次保留下來的是 lexer 與取用端的修正，以及一個新的、機器可驗的不變量。openspec-superpowers-workflow 3.2.1、pr-closeout 1.1.1。

### 11.1 做了什麼試驗

在分支上把兩支 gate 改成只剩 lexer，舊讀法與它們的共用區段刪掉，suite 的 mutant 改打 lexer。先以 bash 當裁判確認「只剩 lexer 時 bash 執行的一個都沒漏」（72 次、之後又 32 次 ×1500 條，零反例），據此退役。接下來一天之內，同一個決定被不同的手段推翻了六次：

| 怎麼發現的 | 形狀 | 為什麼先前的證據看不到 |
|---|---|---|
| 簡化審查 | `--match-head-commit "$(git rev-parse HEAD)"` 讀成沒有 sha 而放行 | harness 不比對 sha 欄，也不生成它 |
| 自審 | `gh api -X PUT "$(echo repos/o/r/pulls/5/merge)"` 放行 | harness 不生成 `gh api` |
| codex | `gh $(true) pr merge 3` 完全沒被認出；`--subject $(true) 3` 檢查了錯的 PR | harness 不生成會消失的替換詞 |
| 多 seed | `EOF=(:<<-a=a=⏎gh pr merge 7 …`（被丟棄的行上、等不到收尾的 heredoc） | 機率約 1／24,000，先前的樣本沒抽到 |
| 大樣本 | `a=(<<"))⏎…`、多行引號當 delimiter | 同上，換個形狀 |

每一個都是 bash 會執行、`b16fb23`（三讀法）擋得住、只剩 lexer 時放行。

### 11.2 根因

1. **證據的結構不對。**「對 bash 零反例」只在 harness 的生成語法與它比對的欄位之內成立；舊讀法多擋的東西大多落在那之外。帶 bash 裁決的超集檢查（`--superset-of … --judge`）也不是獨立證據：它算反例的條件和基本檢查是同一個。
2. **有一類命令 lexer 原理上讀不對。** bash 遇到語法錯誤只丟掉那一行、其餘照跑，那一行上開啟的引號與 heredoc 就不算數（gap 0 的一般形式）。哪一行會被丟要有 bash 的完整語法才知道。lexer「照合法的 bash 讀」，舊讀法是另一套錯法不同的猜測，所以碰巧蓋住其中一部分。
3. **量出來不收斂。** 把只剩 lexer 的 gate 和 `b16fb23` 逐行比對 24,000 條：今天直接擋下 2,148、舊版讀到的是黏了重導向的怪值 458、舊版擋或查了而今天完全沒輸出 639。補上「讀到文字結尾都找不到收尾，其後另當命令讀」（heredoc、算術）之後跑 240,000 條，反例都歸得進已知界線；再跑 190,000 條，又出現兩種新形狀。每多抽一批就多一兩種，補規則沒有終點。
4. **聯集讓 lexer 的錯無害。** 上表六個洞在三讀法下全部擋得住。退役拿掉的正是「新讀法只會多擋」這個保證，而沒有任何證據能取代它。

### 11.3 留下來的東西

- **替換值的標記**（1.1.0 已上線的真漏洞）：lexer 對「字面＋替換」的詞原本只留字面，`gh pr merge 3$(echo 0)` 讀成 PR 3（bash 合併 30）。多數情況舊讀法碰巧擋下，但在只有 lexer 讀得懂的寫法（雙引號內替換裡的雙引號）沒人擋。現在替換在詞裡留標記：引號內與算術是 `\x01`（剛好一個詞），未加引號的 `$( )`／反引號／`${ }` 是 `\x02`（詞數不定，可能一個都沒有）。交給 `bash -c`／`sh -c`／`eval` 的字串會被那個 shell 重新切詞，所以 merge gate 排進佇列前把其中的 `\x01` 換成 `\x02`（自審抓到：只標 `\x01` 時 `bash -c "gh $(true) pr merge 3"` 三種讀法都讀不到，`b16fb23` 讀得到）。當名稱時去掉標記比對；merge gate 當值時視為讀不出——號碼、網址、repo 記為 `-`，sha 不算字面，選項名稱或 `gh api` 端點帶標記、或 `gh` 之後有 `\x02` 的詞，整個 merge 讀不出。archive-gate 照舊以替換為空讀名稱（fail-open）。
- **讀到結尾找不到收尾的地方，其後另當命令讀**：等不到收尾的 heredoc（當它不是 heredoc，同一行其餘的 heredoc 照常）、沒收尾的算術、delimiter 裡沒收尾的引號。原本只有沒收尾的引號這樣做。代價：每個等不到收尾的 heredoc 都把其餘全文掃一遍（找 delimiter，未加引號的再讀一次本體），一條命令裡有數百個時步數撞上 `$LEX_MAX`，merge gate 對含 merge 字樣的命令一律拒絕（實測 600 個時）、archive-gate 只用已讀到的部分。只會多擋；改法（記住第一次找不到收尾、之後查行索引）列為 follow-up。
- **不變量**：在生成的命令上，兩支 gate 回報的不得少於 `b16fb23`——它印的每一行今天都要印，merge gate 另接受一行直接拒絕整條命令的輸出。差分 suite 每次跑（預設語法與一個隨機標點 seed 各 1500 條），並有兩個 canary 證明只留 lexer 會失敗。這是舊讀法存在的理由，也讓它們不需要自己的 mutant：它們是凍結的程式，輸出一變這項檢查就紅。
- **harness**：gh stub 記 repo，merge 要 repo 與號碼都對（或 `-`、或不可能的 repo）才算抓到；四分之一的 merge 帶值替換或會消失的詞；忽略名稱含換行造成的空紀錄。仍不比對 sha 欄（由 merge gate suite 的案例守）。
- **測試分工**：兩支 gate suite 的 mutant 跑在只留 lexer 的副本上（舊讀法會遮蔽 lexer 的錯），各有一個排在最後、只有舊讀法抓得到的案例，並檢查副本只在那一例失敗。

### 11.4 對 mutant 的觀察

改打 lexer 時，mutant「殺不死」或「被別的案例先殺」有三種原因，分清楚後不必逐個試：(1) 同一路徑上有排得更前面的案例，釘到那個案例；(2) lexer 會自我修復——找不到收尾就把其後另讀，所以讀錯只會多擋，bash 當裁判抓不到，要靠「必須放行」的案例（差分 suite 因此拿掉三個 mutant，列為 follow-up）；(3) 突變不改變 suite 看得到的行為，但不代表那行多餘——`<<<` 分支一度因此被刪，逐行比對才發現它在 `<<<<-'…` 上讀法不同，已放回。

### 11.5 之後

第二步不再排程。要重啟的前提是 lexer 能判斷 bash 會丟棄哪一行（gap 0），那等於實作 bash 的語法，不在這個專案的範圍。舊讀法的代價（每支 gate 約 100 行、對極長命令是二次方時間）已記在 follow-ups。（2026-11-14 補記：二次方時間已修成線性，輸出不變——openspec-superpowers-workflow 4.0.1、pr-closeout 1.1.2 的 CHANGELOG。）
